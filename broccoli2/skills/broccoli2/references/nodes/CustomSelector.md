# CustomSelector — селектор из нод

Функция «объект → значение», собранная нодами. Тело — ноды между `CustomSelectorBase` и этим
селектором: от выхода Element базы к входу Output. Потребитель вызывает функцию на каждом
объекте своего потока. Разбор — selectors.md.

Входы
- InputType — тип объекта. Проставляется потребителем, руками не задаётся.
- ResultType — желаемый тип ответа. Тоже от потребителя.
- Base — связь с CustomSelectorBase.Base, ровно одна.
- Output — что вернуть для объекта, ровно одна связь. Одно значение — для `Where`, `Sum`,
  `GroupBy`; поток — для `SelectMany`.

Выход
- Result — селектор. Тип ответа — тип того, что пришло в Output.

Что считается внутри, а что снаружи. Внутри — ноды, которые зависят от объекта: всё, что
построено от Element базы. Остальное — например, `Model` и `Properties` над ним — считается один
раз снаружи, и тело получает готовые значения. Внутри работают любые потоковые ноды, якоря, другие
селекторы: селектор внутри селектора — функция внутри функции.

Ограничения
- Для `Where`, `Sum`, `GroupBy` функция обязана дать на объект ровно одно значение. Поток вместо
  значения останавливает проверку при исполнении: в ошибке — сколько значений получено и в какой
  ноде. `GroupBy` с селектором, который отдаёт поток, схема не примет уже при сборке.
- Внутри не сохраняют результат: `SaveError`, `SaveMessage`, `ResultPercentBase`, зависящие от
  объекта селектора, — ошибка сборки. Наружу значение выходит только через Result.
- Без базы или без связи в Output схема не компилируется. Нода, зависящая от объектов двух
  селекторов, ни один из которых не вложен в другой, — тоже ошибка сборки.
- Быстрым фильтром не сворачивается: элементы для него вычитываются из модели. Ставь его после
  отбора по категории и виду.
- Функция считается на каждом объекте заново. «Каждый с каждым» по всей модели — это N × M вызовов:
  сначала разбей объекты на группы (`GroupBy` по листу или уровню) и сравнивай внутри групп.
- Пока селектор не связан с потребителем, тип объекта — Object, и у `Properties` над Element нет
  выходов. `scheme_apply` это учитывает сам: связь от такого выхода он создаёт после связи
  селектора с потребителем.
