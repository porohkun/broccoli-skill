# ExpressionSelector — селектор с кодом

Условие или вычисление выражением на C#: телом лямбды над объектом.

Входы
- InputType — тип объекта. Проставляется потребителем, руками не задаётся.
- ResultType — желаемый тип ответа. Тоже от потребителя.
- Expression — само выражение, текст. Пишется без «e =>»: сразу тело, `e` — объект. Свойства
  объекта — английскими именами, как выходы `Properties`: `e.Category == "OST_Walls"`,
  `e.BoundingBox.Size.Z > 2000`. Доступны `System` и `System.Linq`.

Выход
- Result — селектор. Тип ответа — тип выражения, если он совпадает с ResultType или точнее его.
  Если выражение неявно приводится к ResultType по правилам C# — целое к `double`, — ответ
  приводится. Иначе выход — тип выражения, и потребитель остановит схему при сборке с понятной
  ошибкой. Пока выражение пустое, выход — ResultType.

Выражение проверяется Roslyn'ом до исполнения: ошибки компиляции приходят в `scheme_check`. Язык —
C# 10. Песочницы нет: код исполняется в том же процессе. Вычисление над объектом — и ничего
больше.

Когда брать: условие проще написать, чем собрать нодами, или нужно сравнить то, что нодами не
сравнить, — например, ID (`e.OwnerViewId == 5`). Когда не брать: простой отбор по категории, виду
или параметру — те сворачиваются в быстрые фильтры, а выражение нет.

Ограничения
- `e.GetParameter("...")` вернёт null, если параметра нет: проверяй, иначе проверка упадёт на
  первом таком элементе. Все параметры элемента (`e.Parameters`) при исполнении не читаются.
- Для `SelectMany` не годится: коллекцию объектов модели выражение не вернёт.
- В `SplitBy` не подключается: вариантов ответа он не сообщает.
