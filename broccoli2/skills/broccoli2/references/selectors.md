# Селекторы

Селектор — значение-условие, которое применяется к каждому объекту потока по отдельности.
Тип: `ISelector<Элемент, Результат>`. У фильтров результат `Boolean` — «да/нет»; у `GroupBy` и
`Sum` результат другой: ключ группы или число.

Селектор не фильтрует сам. Он только отвечает на вопрос; отсеивает — та нода, которой он отдан.

## Откуда берутся

| Нода | Что отдаёт |
|---|---|
| `CategoryFilter` | «элемент нужной категории» — единственный селектор, который сворачивается в быстрый фильтр Revit |
| `ParameterFilter` | «параметр сравнился со значением» |
| `CombineFilter` | несколько селекторов, склеенных через И или ИЛИ |
| `CustomSelector` | условие, собранное нодами: от `CustomSelectorBase` через любые вычисления к результату |
| `ExpressionSelector` | условие выражением на C# |

## Кто их потребляет

`Where` — отсеивает. `GroupBy` — берёт ключ группы. `SplitBy` — разводит по выходам. `Sum` —
складывает числа.

## Согласование типов

Потребитель сам объявляет, какой селектор ему нужен, и пишет это в селекторную ноду:

- тип элемента — из типа своего потока;
- тип результата — из своей задачи (`Where` — `Boolean`, `Sum` — число).

Отсюда правило порядка: **сначала связывай поток, потом селектор**. Если селектор подключить
раньше, потребитель ещё не знает тип потока, и согласование пройдёт впустую — селектор останется
под `Object`.

Селектор по более общему элементу подходит потоку из более частных: `ISelector<IElement, Boolean>`
ляжет на поток `IFlow<IElementType>`, потому что каждый тип элемента — это элемент. Обратное
неверно: селектор, написанный для типов элементов, не годится потоку любых элементов.

## Ограничения

- Селектор приходит **ровно одной связью**. Поток селекторов не поддержан ни в одном мире: если
  `CategoryFilter` получил категории связью-потоком, он отдаст поток селекторов, и `Where` такую
  схему не выполнит.
- Несколько условий складывают `CombineFilter`, а не несколько связей в один порт.
- У `CustomSelector` и `ExpressionSelector` внутри действуют ограничения мира выражений —
  см. `expression-world.md`.
